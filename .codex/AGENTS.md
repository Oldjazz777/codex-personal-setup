# Глобальные правила Codex

## Язык
- Общайся по-русски, если пользователь не попросил иначе.

## Рабочие договорённости
- Первым сообщением новой сессии запускай `/brainstorming`; для простой задачи достаточно коротко: что понял, что предлагаешь, и запросить подтверждение.
- Файлы можно читать и анализировать без запроса. Перед нетривиальным редактированием покажи чек-лист и дождись явного «да».
- Перед ТЗ, спецификацией, документацией или существенным кодом уточняй только развилки, меняющие результат. Стек определяй по `AGENTS.md` и манифестам проекта, не по догадкам.
- Не редактируй `.env`, `keys.json`, `credentials.json` и конфиги с секретами. Не выводи значения секретов в чат или контекст.
- Подбирай релевантный скилл и спрашивай: «Ситуация X → запускаем /скилл или пропускаем?».
- После изменения кода предлагай `/review` до заявления о готовности. Перед утверждениями «готово», «работает» или «тесты прошли» показывай результат проверки или запускай `/verification-before-completion`.

## Статус задачи
- При закрытии задачи предложи `/task-status`. Если пользователь уходит («продолжу завтра», «на сегодня всё»), выдай статус сразу: сделано, непроверенное, дальше по порядку, блокеры.

## Делегирование
- Используй субагентов только для независимых крупных направлений; не делегируй пару чтений файла, простой поиск или мелкую правку.
- `architect` — системная и межсервисная архитектура, только чтение; `researcher` — исследование и карта фактов, только чтение; `mechanic` — однозначная механика по чёткой инструкции.
- Для сложной архитектуры предложи `architect`; для 2+ независимых крупных направлений используй `/dispatching-parallel-agents`, для задач одного плана — `/subagent-driven-development`.
- Не более 20 параллельных агентов без явного запроса. Не переделывай работу субагента, а проверяй и интегрируй его результат.

## Триггеры
1. Первое сообщение — `/brainstorming`.
2. Ошибка или «не работает» — `/systematic-debugging` до фикса.
3. «Сделай», «добавь», «реализуй» — `/build`.
4. Перед production-кодом — `/test-driven-development`.
5. Фидбек ревьюера — `/receiving-code-review`.
6. Тесты прошли / работа завершена — `/verification-before-completion`.
7. «Статус», «итоги», «что осталось» — `/task-status` сразу.
